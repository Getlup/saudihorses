# منصّة المِرباط — نظام إدارة الإسطبلات وحجز الفروسية

نموذج **جاهز للإنتاج** مبني بـ Python (Flask) — يشمل: إدارة الخيول والسجل اليومي، صفحة خاصة
لكل مالك خيل، حجز حصص الركوب/التدريب بباقات مدروسة على السوق السعودي، دفع (بوابة تجريبية قابلة
للاستبدال)، وتقييم الحصان والتجربة.

## ما الذي يجعله جاهزًا للإنتاج

- **قاعدة بيانات**: PostgreSQL في الإنتاج عبر `DATABASE_URL`، وSQLite تلقائيًا محليًا للتطوير السريع (Flask-SQLAlchemy، لا حاجة لتغيير الاستعلامات)
- **الترحيلات (Migrations)**: عبر Flask-Migrate/Alembic بدل حذف/إعادة إنشاء الجداول — تُطبَّق بأمر `flask db upgrade`
- **CSRF Protection**: كل نموذج (form) في الموقع محمي برمز CSRF (Flask-WTF) — أي طلب تعديل بدونه يُرفض تلقائيًا
- **حدود معدل الطلبات (Rate Limiting)**: 10 محاولات دخول/تسجيل بالدقيقة لكل عنوان IP — حماية من هجمات تخمين كلمات المرور
- **ترويسات أمنية** على كل استجابة: X-Frame-Options، X-Content-Type-Options، Referrer-Policy، Strict-Transport-Security
- **صلاحيات مُحكمة**: كل مسار يتحقق أن المستخدم يملك فعلًا الحجز/الحصان الذي يحاول الوصول إليه (وليس فقط أنه مسجّل دخول) — تم اختبار ذلك آليًا
- **رفع صور آمن**: التحقق الفعلي من محتوى الملف (وليس امتداده فقط) عبر Pillow، أسماء ملفات عشوائية (UUID) لمنع تخمين المسارات
- **معالجة أخطاء نظيفة**: صفحات 403/404/500 مخصصة لا تُسرّب تفاصيل تقنية للمستخدم، مع تسجيل الخطأ في السجلات (logs) داخليًا
- **رفض الإقلاع بدون إعداد آمن**: التطبيق يرفض العمل في وضع الإنتاج بدون `SECRET_KEY` حقيقي
- **فحص صحة** (`/healthz`) تستخدمه منصة الاستضافة للتأكد أن التطبيق وقاعدة البيانات يعملان
- **مجموعة اختبارات آلية** (12 اختبارًا عبر pytest) تغطي المصادقة، CSRF، الصلاحيات، وتدفق الحجز الكامل — كلها ناجحة

## التشغيل محليًا (تطوير)

```bash
cd mirbat
python3 -m venv venv
source venv/bin/activate        # على ويندوز: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# افتح .env وضع SECRET_KEY عشوائيًا:
python -c "import secrets; print(secrets.token_hex(32))"

# إنشاء الجداول عبر الترحيلات (وليس db.create_all)
flask db upgrade

# بيانات تجريبية (مربط العز — 3 ملّاك × 10 خيول)
python seed.py

# التشغيل
python app.py
```

افتح المتصفح على: **http://127.0.0.1:5050**

## تشغيل الاختبارات الآلية

```bash
pip install pytest
pytest -v
```

12 اختبارًا يغطون: تحميل الصفحات العامة، رفض الدخول بكلمة مرور خاطئة، رفض أي طلب تعديل بدون
رمز CSRF، رفض كلمات المرور القصيرة، منع الزوار من الوصول للوحات الإدارة، منع أي مستخدم من رؤية
حجز/حصان مستخدم آخر، وتدفق الحجز الكامل من الاختيار حتى تأكيد الدفع.

## النشر على الإنترنت (Render — الأسهل للبدء)

1. ارفع المشروع إلى مستودع GitHub خاص (تأكد أن `.env` و`venv/` و`mirbat.db` غير مرفوعة — موجودة في `.gitignore`)
2. في Render: **New → Blueprint**، اختر المستودع — سيقرأ Render ملف `render.yaml` تلقائيًا وينشئ خدمة الويب وقاعدة بيانات PostgreSQL معًا، ويولّد `SECRET_KEY` عشوائيًا
3. بعد أول نشر، شغّل مرة واحدة من "Shell" في لوحة Render: `flask db upgrade` ثم (اختياريًا) `python seed.py` لبيانات تجريبية أولى
4. اربط نطاقك (دومين) من إعدادات الخدمة — SSL يُفعَّل تلقائيًا ومجانًا

## البنية

```
mirbat/
├── app.py              # التطبيق والمسارات (routes) — مُحصَّن أمنيًا بالكامل
├── config.py            # الإعدادات (تُقرأ من متغيرات البيئة)
├── models.py            # نماذج قاعدة البيانات + فهارس (indexes) للأداء
├── wsgi.py              # نقطة الدخول لـ Gunicorn في الإنتاج
├── seed.py              # بيانات تجريبية مطابقة لسيناريو "مربط العز"
├── requirements.txt      # نسخ محددة (pinned) من كل حزمة
├── Procfile             # أمر تشغيل Gunicorn + تطبيق الترحيلات عند كل نشر
├── render.yaml           # نشر بضغطة واحدة على Render
├── .env.example          # نموذج متغيرات البيئة (لا تضع أسرارًا حقيقية بالكود أبدًا)
├── migrations/           # ترحيلات Alembic (تُدار بأمر flask db)
├── tests/test_app.py     # 12 اختبارًا آليًا
├── templates/            # صفحات HTML (Jinja2) بتصميم فخم عربي RTL
│   └── errors/           # صفحات 403/404/500 مخصصة
└── static/
    ├── css/style.css     # نظام التصميم
    └── uploads/          # صور الخيول والسجلات اليومية المرفوعة
```

## الأدوار الثلاثة في النظام

1. **مالك الإسطبل** (`/admin`) — يضيف الخيول، ينفّذ مهام السجل اليومي المنظّمة لكل حصان، يدير الموظفين ومالكي الخيول، ويراجع حجوزات الزوار.
2. **مالك الخيل المُودَع** (`/owner`) — صفحة خاصة للاطلاع فقط على حالة خيوله المستضافة.
3. **الزائر/المتدرب** (`/book`) — يسجّل حسابًا، يختار باقة، يدفع، ثم يقيّم الحصان والتجربة.

## تصدير PDF (تقرير يومي + فاتورة حجز)

- **تقرير المتابعة اليومي**: من صفحة "مهام اليوم" لأي حصان، زر "تصدير التقرير PDF" — يولّد تقريرًا مطابقًا لهوية المنصة البصرية بكل مهام ذلك اليوم وحالتها.
- **فاتورة الحجز**: من صفحة تأكيد الحجز (أو من لوحة الإدارة)، زر "طباعة الفاتورة".
- التوليد عبر `reportlab` مع رسم يدوي مباشر على الـ canvas (وليس عبر `Paragraph`) لأن كلاس `Paragraph` في reportlab يُفسد النص العربي المُهيَّأ مسبقًا لعرضه من اليمين لليسار. خط **Amiri** هو الوحيد المستخدم في الـ PDF (خط Tajawal الشبكي ينقصه بعض أشكال الحروف العربية المطلوبة لهذا الأسلوب من العرض).
- الشعار والخطوط مُضمَّنة داخل المشروع (`static/img/logo.png`, `static/fonts/`) — لا حاجة لاتصال إنترنت وقت توليد الملف.

## خطوات لاحقة مقترحة (حسب النمو)

- استبدال بوابة الدفع الوهمية في `/checkout` ببوابة حقيقية مثل **Moyasar** أو **HyperPay** (تتطلبان نطاقًا فعليًا بـ HTTPS وسجلًا تجاريًا)
- رفع الصور إلى تخزين سحابي (Cloudflare R2 / AWS S3) بدل القرص المحلي — ضروري إن استضفت على منصة "تُصفّر" القرص مع كل نشر
- استخدام Redis بدل الذاكرة المحلية لتخزين حدود معدل الطلبات (`RATELIMIT_STORAGE_URI`) إذا شغّلت أكثر من عامل/خادم واحد
- إشعارات SMS/واتساب لتأكيد الحجوزات
- توسعة تعدد المرابط (multi-tenancy) بالكامل — القاعدة مُجهزة أصلًا (كل الجداول مرتبطة بـ `stable_id`)
